# Telegram Chat через GREEN-API

Тестовое задание: компактный React-интерфейс для отправки и получения текстовых сообщений Telegram через GREEN-API.

## Возможности

- подключение по `apiUrl`, `idInstance` и `apiTokenInstance`;
- проверка состояния инстанса перед входом;
- восстановление списка чатов Telegram при входе;
- просмотр контактов телефонной книги Telegram и открытие чата по выбранному контакту;
- отображение аватаров и уточнение данных личных контактов через `getContactInfo`;
- поиск получателя по телефону или `@username`, а также прямое открытие по `chatId:`;
- отправка текстовых сообщений;
- загрузка до 100 последних текстовых сообщений при первом открытии чата;
- обработка ошибок отправки по уведомлениям о статусе сообщения;
- последовательное получение и подтверждение входящих уведомлений;
- адаптивный интерфейс в визуальной логике Telegram Web;
- состояния загрузки, пустых данных и ошибок.

Исходное задание допускает реализацию для Telegram или WhatsApp, если вариант для MAX недоступен. Этот проект реализует вариант для Telegram.

История загружается при первом открытии чата в текущей сессии; вручную её можно запросить повторно. Загружаются последние 100 сообщений, подгрузки более старых сообщений нет. Список чатов и контактов при новом входе восстанавливается из GREEN-API, но локальное состояние приложения между сессиями не сохраняется.

## Архитектура

- `App` координирует экран подключения и рабочее пространство; подключение вынесено в `useGreenApiSession`.
- `api/greenApi.ts` содержит типизированный HTTP-клиент, а `api/greenApiApi.ts` — RTK Query endpoints и контроллерные сценарии.
- RTK Query cache — единственное runtime-хранилище чатов, контактов и сообщений. Нормализация и преобразование DTO находятся в `data/`; очередь уведомлений запускается и отменяется вместе с подпиской на рабочее пространство.
- Узловые компоненты содержат собственные `components/`, `hooks/`, `types.ts` и CSS Modules там, где они нужны. Общий `ChatAvatar` находится в `shared/components`.

## Локальный запуск

```bash
npm install
npm run dev
```

Для production-сборки:

```bash
npm run build
npm run preview
```

Перед использованием создайте и авторизуйте Telegram-инстанс в личном кабинете GREEN-API и настройте получение входящих уведомлений (см. ниже). Значения `apiUrl`, `idInstance` и `apiTokenInstance` вводятся в форме приложения, используются браузером для прямых запросов к GREEN-API и не сохраняются в `localStorage`. После перезагрузки страницы подключение нужно выполнить заново.

При входе список существующих чатов загружается через `getChats`, а телефонная книга — через `getContacts`. Историю выбранного чата приложение затем запрашивает отдельно.

## Настройки инстанса GREEN-API

Для получения входящих сообщений включите в настройках инстанса переключатель «Получать уведомления о входящих сообщениях и файлах». Так как приложение использует очередь HTTP API (`ReceiveNotification` / `DeleteNotification`), поле URL вебхука должно оставаться пустым. После сохранения настройки могут применяться до пяти минут. [Инструкция GREEN-API по настройке инстанса](https://green-api.com/telegram/docs/cabinet/settings/) · [Получение уведомлений через HTTP API](https://green-api.com/telegram/docs/api/receiving/technology-http-api/).

Очередь читается последовательно: приложение обрабатывает уведомление и удаляет его по `receiptId`. Если GREEN-API не подтверждает удаление, чтение останавливается и интерфейс показывает ошибку, чтобы не зациклиться на одном событии.

Сведения и аватары личных чатов подгружаются через `getContactInfo`, когда чат появляется в видимой области списка или открывается. Результат запоминается до конца текущей сессии: успешная загрузка не повторяется после перемонтирования аватара, а после трёх неудачных попыток дополнительная информация считается отсутствующей. В последнем случае уже загруженные через `getContacts` имя и другие данные сохраняются. Для распознанных групп и каналов приложение оставляет инициалы.

Фон окна чата хранится локально в `public/assets/chat_bg-2.80514.png` и подключается приложением по адресу `/assets/chat_bg-2.80514.png`.

## Использованные методы

- `getStateInstance`
- `getChats`
- `getContacts`
- `getContactInfo` (включая аватар)
- `checkAccount`
- `sendMessage`
- `getChatHistory`
- `receiveNotification`
- `deleteNotification`

Поддерживаются входящие текстовые сообщения и ошибки отправки; медиа и другие типы сообщений не отображаются.

В репозитории также есть конфигурация Caddy `green.thnel.caddy` для SPA-домена `green.thnel.com` и перенаправления `www.green.thnel.com`. Перед использованием проверьте и при необходимости измените `root` на каталог с production-сборкой на целевом сервере.
